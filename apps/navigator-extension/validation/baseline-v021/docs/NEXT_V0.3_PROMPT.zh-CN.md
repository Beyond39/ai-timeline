# 对话航图 V0.3 · 可直接交给 Codex 的实施提示词

请继续在 `D:\mytools\GPT-SaaS` 的现有工程中直接开发 AI Conversation Visual Navigator 浏览器插件。当前源码是 `apps/navigator-extension`，V0.2.1 已完成一轮实际审查、修复和回归。请先阅读该目录的 README、`docs/REVIEW_FIXES_2026-10-03.zh-CN.md`、`docs/DATA_CONTRACT.zh-CN.md` 和 `docs/DELIVERY.zh-CN.md`，再核对代码真实状态，不要依据文档猜测实现已经完成。

这轮目标是交付可安装的 V0.3.0：让真实 ChatGPT 采集更容易诊断，让完整问答读起来更接近原对话，并让单个项目或 Q/A 的读取不会总把全部本地正文载入内存。请直接实施、运行必要测试、修复失败、生成安装包。遇到常规可逆的实现选择自行决定并说明，不要只停在方案或等我确认。

## 一、必须保留的现有能力

继续做浏览器插件，使用现有 Manifest V3、中文界面、IndexedDB 和本地项目。规则 / 模型建议预览、确认、拒绝、人工标题 / 主题 / 连续边界、撤销、备份与原文版本必须继续可用。保留原 Python 工程作为参考，不重写为 SaaS、不引入账号收费或必需常驻服务器。

每条用户消息必须形成真实 Q/A，含未回答、多条助手消息、工具 / 辅助消息和内容缺失状态。Segment 成员明确、连续、不重叠、按原路径顺序覆盖；不要把短摘要或整理标题当作正文。原文、源身份、路径、历史版本、快照、整理证据及人工修订仍能追溯。

重点保护 V0.2.1 的回归：改名 / 改主题不换掉历史证据；拆合保留两侧证据与复核状态；补采遗漏用户问题后当前归属更新而历史归属仍可备份；最新预览按时间及持久序号选取；Unicode 搜索 / 高亮映射回原文；并发首次数据库读取共用连接；缓存不掩盖写入后的过期判断。

## 二、P0：采集诊断和覆盖状态，做到可实际定位问题

1. 复查 `adapters/chatgpt.js` 的 detect / collect / normalize 与后台调用。将选择器、稳定消息 ID 和结构读取继续集中在适配器内；区分页面不支持、未加载消息、页面结构变化、来源标签失效 / 无授权及正文不可取得。
2. 在现有采集预览中展示用户能理解的信息：实际取得消息数、角色 / 回答组情况、有无可靠源 ID、是否生成中、附件是否只有引用、已取得范围及缺失原因。详细技术信息放到可折叠的诊断区域，不把代码字段堆在主要使用流程。
3. 诊断复制默认只包含适配器版本、页面类型、计数、能力状态及错误原因，不包含正文、账号、完整 URL / 项目名或其他私人内容；用户若主动选择附加内容，应先显示将包含什么。
4. 不将当前 DOM 的消息数量宣传为完整历史；不猜原生项目、未展示分支和来源时间。页面滚动后补采可以合并已有可靠身份，不能因没再显示旧消息而删除记录。
5. 为普通对话、项目内对话、流式更新、重复文本不同 ID、未回答、工具、附件仅引用、补采中间问题及结构识别失败建立明确标记的适配器样例。针对观察或代码中实际存在的失败增加回归，不编造当前网站页面结构。
6. 如果已有连接到真实 Chrome / Edge 的控制能力，先检查已安装插件并沿用原条目 / 原加载目录测试；缺少能力或登录状态时记录未验证项和具体手动步骤，不能用内置浏览器桥接测试冒充扩展权限或真实页面验收。

## 三、P1：完整正文阅读，保持安全和版本可追溯

1. 在现有 Reader 中增强段落、标题、列表、引用、代码块、行内代码、表格和 Markdown 的展示。长回答保留完整内容，折叠与展开只影响显示。增加复制整条正文、复制代码和明确的原文查看入口。
2. 明确导入 Markdown 与 DOM 采集文本 / 结构的区别。DOM 采集如确实取得代码 / 表格结构，保存可验证的结构化表示和原始可读文本；拿不到的格式就保持普通文本，不伪造 Markdown 或“原页面完整还原”。
3. 渲染和原文分开，历史正文不可变。搜索高亮、Q/A 切换、消息定位、工具折叠及整理引用版本定位继续工作；引用的是历史版本时明确标注，不只跳到最新正文。
4. 不将来源 HTML 直接作为可执行内容插入。若采用 Markdown 或清理库，依赖打包在插件本地，限制协议、事件属性和脚本；外部图片 / 链接默认不自动请求，遵守现有离线约束。公式拿不到或本地渲染未支持时保留原表达式，并如实说明支持范围。
5. 保持中文三栏和侧栏可读，主题颜色一致，状态同时有文字标识。对代码横向滚动、表格、很长文本和窄侧栏做界面核对，避免正文被截掉。

## 四、P1：按项目 / 对话范围查询，减少整库读写

1. 先统计 `readState()` 的调用路径、重复读取、正文副本和建议 / 整理包加载量，区分地图摘要、Q/A 正文、完整对话分页、搜索、写入与备份的不同需要。
2. 使用已有 IndexedDB projectId / conversationId 索引及必要的最小索引，增加范围查询接口。项目地图只取该项目必要导航摘要；点开 Q/A 只加载相关消息及需要的版本；不要为了一个 Q/A 读所有项目和所有整理包正文。
3. 搜索返回有限页面和稳定位置，读取正文可分批或使用游标；中文、全角、组合字符与跨长正文的命中继续正确。不要为了分页而截断原文或漏掉其余命中。
4. 写入保留原子事务、修订冲突和建议过期检查，不简单去掉版本校验来换速度。数据库迁移若确实需要，按最小增量执行，兼容旧记录 / V0.1 / V0.2 备份；保留同一扩展加载目录。
5. 使用明确标记的多项目 / 长对话样例比较改造前后，记录打开项目、读取单轮、分页搜索和重复建议的耗时、读取范围与可观察数据量。样例至少有 500 轮和 2,000 轮，另有无关项目用于验证没有被整库载入。不要只给理论复杂度或一次漂亮数字；准确写出机器 / 环境、规模、重复次数和排除项。

## 五、P2：基础能力完成后继续推进地图浏览

不要同时做所有地图形态。上述 P0 / P1 达到可用后，优先增加“项目 → 对话 → 片段 → Q/A”的层级展开或语义缩放，以同一组稳定 ID 联动 Reader、搜索和选中状态。每一级展示真实对象及计数，并允许回到上一级；主题颜色继续复用。

如果继续增加 Tree，明确它是主题归类视图；同主题不自动生成因果线。思想关系后续应另存人工 / 模型声明、关系类型、两端引用、原文证据和确认状态。时间过滤只能使用可靠来源时间；未知时间单独显示，不能用采集时间替代讨论时间。先完成一种可用视图，再考虑 Story、关系图和可选模型调用。

允许做小范围界面改进，但不要因此延后数据能力；过期建议与当前待办可区分，历史建议采用可恢复归档，不自动删除原文证据。
