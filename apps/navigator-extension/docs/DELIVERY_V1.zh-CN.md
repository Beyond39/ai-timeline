# 对话航图 V1 功能版 · 2026-10-10

安装版本 **1.0.0**，采集器 **chatgpt-dom-v7**。本轮实现完整回答读取兼容、明确来源重新绑定、本地记忆恢复点、可保存的资料包、跨 Conversation 关联与新 UI。它是供真实环境验收的 V1 功能候选版；当前登录 GPT、原生 Chrome／Edge 权限、实际 Word／WPS 和打印文件仍未由本轮工具验收。

## 这次“没有回答”的直接原因

用户提供的错误是 `source_changed`，消息数为0，正文能力为 `not_checked`：来源标签已经打开另一条 Conversation，后台在采集正文前拒绝了旧绑定。旧后台错误诊断把适配器版本固定写成v5，不能据此推断当前页面结构或实际安装版本。

现在失败窗口提供“重新绑定当前 Conversation”。核对来源标题与地址后，点击“绑定这条 Conversation 并采集”；预览后页面再改变仍会安全拒绝。普通采集继续只读明确绑定的来源，不自动跳去其他标签。没有授权时，仍须在目标 GPT 页点工具栏插件图标。

采集器也修复了独立的漏回答边界：任意标签的明确说话人属性、无旧CSS的回答、同一main内thread之外的回答，以及通用section内多轮正文。Q1／A1／Q2／A2不会被合并为一段；回答中的多段代码、表格和尾部保留。无法确认角色时保留未知正文，不按排版或交替顺序猜助手。少量未确认正文默认一起展开，避免只看到第一段问题。

## 已实现的功能

| 能力 | 实际行为 |
| --- | --- |
| 完整阅读 | 项目 → Conversation → Q/A；中间直接读完整回答、目录跳转、小箭头折叠、树状／蛇形节点、图形缩放；工具不占助手回答编号 |
| 本地记忆 | 沿用原资料库；新版首次打开为已有资料建立恢复点；手动恢复点、整个资料库导出／导入，恢复创建独立新项目 |
| 历史保留 | 正文更新保留不可变旧版本，人工阅读标签、整理和来源仍在；恢复点独立保存，不嵌套到日常写入 |
| V0.8 资料包 | 保存制作方案、关闭后重开、章节与正文顺序、重命名／另存、归档／恢复；方案固定确切版本，不自动换成新版回答 |
| 独立打印 | 持久打印快照和独立print.html；打印页面可以重开，正文由真实保存的版本重建，不使用调用方传入的正文 |
| V0.9 关联 | 相关、支持、不同观点、依赖四种人工关系；两端绑定具体消息版本，能跳回当时的完整正文；归档可恢复 |
| 建议归档 | 在“记忆”中归档／恢复旧整理建议，保留原文和证据；过期并发操作拒绝 |
| 新 UI | 暖白、深墨和紫色；16px正文、舒适行距；宽窗口目录在旁，窄窗口纵向；搜索、导出和资料包常显，来源／记忆／关联有独立入口 |

“记忆”在这里指本地资料与历史的持久保存，不代表自动上传给模型、调用付费API或自动生成语义知识。

## 更新步骤

1. 先用旧版本导出重要项目备份，关闭旧插件页面。
2. 沿用**原扩展条目、原加载目录、原浏览器配置**更新。标准目录和源码由构建更新：

   `D:\mytools\GPT-SaaS\apps\navigator-extension\dist\ai-conversation-visual-navigator`

   若原来加载其他位置的解压副本，把本版ZIP内容覆盖到那个原目录，再刷新原条目。不要通过卸载重装来升级。
3. 确认扩展版本1.0.0，重新打开插件。已有资料会原地保留，并建立升级前恢复点。
4. 在目标GPT页点工具栏图标后采集；若提示来源变化，使用新窗口中的重新绑定入口。预览检查用户和助手数量、回答开头、代码、表格及最后一句，再保存。
5. 旧采集没有保存的答案不会凭版本号自动出现，需要重新采集。旧的混合未知正文保留，需要依据实际新采集或人工标注阅读。

ZIP：`dist/ai-conversation-visual-navigator-v1.0.0.zip`。无需Python、API Key或npm安装。没有新增扩展权限。数据名称不变，IndexedDB由3增量升级到4，新增方案、打印、关联和恢复点；旧业务记录不重建。备份继续Schema2，新数组缺省兼容旧备份。

## 数据保留的实际范围

更新不清库，恢复不覆盖原项目。升级恢复点和日常资料仍属于原浏览器的扩展身份；卸载扩展、清除浏览器资料、换用户配置或换扩展ID不受本地数据库控制，需用导出的资料库备份恢复。V4资料库不能直接让旧V3应用降级打开，应使用本版或导出备份。

资料包、打印快照或跨会话关联引用中的Conversation不能单独搬到另一个项目，以免证据跨项目失效；可用项目备份复制恢复到新项目。未引用的旧移动功能保留。当前没有自动语义关联、完整未加载历史采集、未展示分支或附件正文下载。

## 验证与交付标准

本轮 **242项Node检查、233项浏览器及页面操作检查通过**。检查分开记录于`dist/V1_*REPORT.json`及现有Node报告：采集与来源绑定、真实V3→V4旧数据逐行比对、恢复点与资料库恢复、资料包历史版本、独立打印页、跨会话证据、Q/A和两种图形，以及390／260像素实际应用视口。

所有浏览器样例均明确合成，使用隔离IndexedDB。窄视口在固定尺寸同源iframe中加载完整应用，不冒充原生扩展侧栏；浏览器API在本地桥接，验证代码不进入安装包。Node生成的DOCX结构与正文检查不替代Word／WPS视觉验收；打印页DOM检查不替代实际PDF分页验收。最终检查数量见验证汇总，未新测大规模真实性能。

真实验收优先顺序：普通／项目内GPT均读到Q与完整A → 原资料和旧版本仍可读 → 资料包重开与关联出处 → 实际DOCX／PDF → 长期规模和兼容维护。达到这些实际门槛后，才称为稳定V1。
