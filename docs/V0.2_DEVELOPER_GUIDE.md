# V0.2 开发与使用指南

## 本版本解决什么

V0.2 把 V0.1 的“可查询事实库”升级成“可重编译知识库”。它从项目、对话、消息和句子中找出主题，把跨对话证据归到同一主题，生成正常文件夹结构的 Markdown 知识文件，并保存每次内容变化形成的修订。所有文件默认处于 `needs_review`，必须人工确认才能成为 `approved`。

## 默认模式为什么不调用外部 AI

`heuristic` 是可重复、零成本、隐私友好的基线提取器。它使用明确关键词规则验证完整数据通路，效果不会伪装成高级语义理解。选择 `--extractor openai` 后才会发送本次编译范围内的句子；API Key 只从环境变量读取，响应使用 JSON Schema，并验证每个证据 ID 都真实存在。

## 快速开始

```powershell
python -m ai_memory init
python -m ai_memory import examples/learning-project.json
python -m ai_memory compile
python -m ai_memory topics
python -m ai_memory topic 学习方法
python -m ai_memory knowledge
python -m ai_memory review 学习方法 approve --note "已核对原文"
```

打开 `output/knowledge/README.md` 可以看到知识目录。每个主题位于独立目录，例如 `output/knowledge/学习方法/README.md`。

## 知识文件结构

每个文件包含：

1. 核心归纳：本主题的简短范围说明。
2. 可追溯核心内容：优先展示助手回答，并带证据编号。
3. 相关问题：保留用户原始问题，不与答案混为一谈。
4. AI 扩展：明确标记为非原始证据。
5. 来源与证据坐标：项目、对话、角色、句子 ID、消息 ID 和字符范围。
6. 审核提示：提醒用户检查主题边界、上下文与冲突。

## 增量与修订

编译器根据所选范围内的句子 ID 和文本计算 SHA-256 指纹。内容没有变化时再次编译会返回 `skipped`。使用 `--force` 可以重新运行提取器，但若生成内容哈希没有变化，不会创建重复修订。新增会话改变了某个知识文件时，修订号递增，并把原有 `approved` 状态重置为 `needs_review`。

## 人工审核

```powershell
python -m ai_memory review 学习方法 approve --note "证据完整，主题边界正确"
python -m ai_memory review 学习方法 reject --note "混入了课程专属内容"
python -m ai_memory review 学习方法 reset
```

审核事件单独写入 `review_events`，不会伪装成模型生成记录。知识目录会同步显示当前审核状态。

## 可选 OpenAI Responses API

```powershell
$env:OPENAI_API_KEY="你的密钥"
python -m ai_memory compile --extractor openai --model "你明确选择的模型ID"
```

可用 `--max-input-chars` 设置一次发送的最大字符数。超过限制时程序会停止，而不是静默截断。默认请求 `store: false`，但外部服务的数据处理仍应由使用者根据自己的账户和隐私要求确认。

## V0.2 API

- `GET /health`
- `GET /v0/topics`
- `GET /v0/topics/{topic_id_or_slug}`
- `GET /v0/knowledge-documents`
- `GET /v0/knowledge-documents/{document_id}/revisions`

V0.1 的项目、问题、搜索和消息接口继续保留。V0.2 的 HTTP 接口仍然只读，编译与审核由本地命令执行。

## 新数据库表

- `compiler_runs`：编译范围、提取器、模型、来源指纹和结果。
- `topics`：稳定主题、摘要、AI 扩展和状态。
- `topic_evidence`：主题与原始句子的多对多关系。
- `knowledge_documents`：文件路径、当前修订和审核状态。
- `document_revisions`：不可覆盖的内容修订历史。
- `review_events`：人工批准、驳回和重置事件。

## 明确限制

- 默认规则适合演示和回归测试，不是通用语义模型。
- OpenAI 提取器一次处理一个编译范围，尚未实现自动分块与跨块合并。
- 没有相似主题合并界面、冲突检测和证据权重学习。
- 来源删除后尚未自动标记所有受影响知识。
- 本地 API 没有登录与权限隔离，禁止直接公开到互联网。
- Markdown 文件是数据库状态的可读投影；数据库仍是修订与审核的权威来源。

## 建议学习顺序

1. 读懂 `compiler.py` 如何从句子变成主题和文件。
2. 理解多对多关系 `topic_evidence`。
3. 理解内容哈希、来源指纹与修订去重。
4. 修改 `heuristic.py` 的关键词并观察生成文件变化。
5. 学习 JSON Schema 后再研究 LLM 提取器。
6. 最后再做前端主题树、证据抽屉和审核按钮。
