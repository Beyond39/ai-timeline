## 2. 为什么现在不需要训练模型

这个产品当前需要的是一个“可靠的处理系统”，而不是自己训练一个大模型。导入、拆分、哈希、缓存、证据绑定、主题文件、审核和版本历史都属于普通软件与数据库能力；理解问题、生成摘要和提出主题候选，可以调用现有 LLM 完成。

当前推荐组合是：现有 LLM + 结构化输出 + 本地数据库 + 精确哈希 + 相似度候选 + 人工复核。只有在积累了稳定分类体系、数千条人工标注样本、明确失败模式和评测集以后，微调或训练小模型才有经济意义。

本轮默认流程仍完全离线。离线规则的职责是验证产品闭环，不冒充成熟语义模型。用户未来显式选择 OpenAI 提取器、模型 ID 和自己的 API Key 时，才会发生外部模型请求。

## 3. 正确的数据流水线

系统采用 Map-Reduce 思路。Map 阶段逐条对话处理，避免一次把所有聊天塞进模型；Reduce 阶段再把跨对话 Q/A 与句子归入主题，生成知识文件。

```text
用户授权导出的数据
        |
        v
Project -> Conversation -> Message -> Sentence     原始事实层
                        |
                        v
               Question + Answer -> Q/A Unit       V0.2.1 Map
                        |
             exact hash / alias / merge review
                        |
                        v
              Topic <-> Q/A <-> Evidence            V0.2.1 Reduce
                        |
                        v
Knowledge File -> Revision -> Human Review          V0.2
                        |
                        v
Summary UI / Timeline / Context Package             V0.3
```

最重要的约束是：派生内容永远不能覆盖原始消息。即使 AI 摘要错误，用户仍能沿 topic -> Q/A -> sentence -> message -> conversation -> project 回到来源。

## 4. V0.2.1：Q/A 单元怎样产生

系统先读取一条对话中的问题及直接回答。每一对问题与回答形成稳定 Q/A ID，保存问题原文、回答原文、候选摘要、内容 SHA-256、处理器版本和状态。问题句与回答句分别写入证据关系。

一个大问题可以继续拆成多个 Q/A 单元；一个 Q/A 也可以属于多个主题。例如示例中的“如何安排每周复习计划？我希望兼顾专业课和英语”同时关联学习规划、学习方法、专业课学习和英语学习，但它的原始位置仍只有一个。

| 对象 | 权威程度 | 能否被 AI 改写 | 作用 |
|---|---|---|---|
| Message / Sentence | 原始事实 | 不允许 | 保存原话与位置 |
| Question / Answer link | 结构事实 | 只允许重新识别 | 表示问答关系 |
| Q/A Unit summary | 派生候选 | 允许重算 | 便于浏览和归纳 |
| Topic label | 派生候选 | 允许归并 | 建立跨对话结构 |
| Knowledge document | 阅读投影 | 允许修订 | 供人学习与复用 |
| Review event | 人工判断 | 不覆盖历史 | 记录批准或退回 |

## 5. 哈希到底负责什么

哈希不是语义理解工具。V0.2.1 使用 SHA-256 处理精确身份、重复数据、缓存与修订：文件哈希判断同一导出是否已导入；句子哈希标记正文；Q/A 内容哈希标记问题与回答组合；规范化标签哈希标记精确别名；对话来源哈希与处理配置共同形成缓存键；知识内容哈希决定是否创建新修订。

```text
cache_key = SHA256(
  conversation_id
  + conversation_source_hash
  + extractor_version
  + prompt_version
  + model_name
)
```

“学习 方法”和“学习方法”规范化后可得到相同哈希；“学习技巧”和“学习方法”即使人认为接近，也会得到不同哈希。后者必须进入语义候选或人工判断，不能靠哈希放进同一桶。

## 6. 标签归并的安全策略

标签解析分成三层。第一层是规范化后的精确命中，自动使用已有主题。第二层是已经批准的别名，例如人工确认“复习规划”属于“学习规划”，以后可以直接复用。第三层是相似候选，只生成 merge review。

| 判断结果 | 系统动作 | 是否需要人 |
|---|---|---|
| 精确规范化标签相同 | 直接关联已有主题 | 否 |
| 命中已确认别名 | 直接关联别名指向主题 | 否 |
| 文字相似但未确认 | 建立待判断任务 | 是 |
| 明显不同 | 建立新候选主题 | 后续审核 |

人工选择 merge 后，Q/A 关系与别名迁移到目标主题，候选主题标记为 merged；选择 keep_separate 后，两者继续独立。相似度绝不会单独成为最终事实。

## 7. V0.2.1 的数据库变化

本轮数据库版本升到 4，保留旧数据并自动补充编译配置字段。新增六张表：analysis_cache、qa_units、qa_evidence、topic_aliases、qa_topics、merge_reviews。

| 表 | 关键字段 | 解决的问题 |
|---|---|---|
| analysis_cache | cache_key、source_sha256、prompt_version | 相同对话不重复处理或付费 |
| qa_units | question_text、answer_text、content_sha256 | 把混杂对话拆成可复用问答 |
| qa_evidence | qa_unit_id、sentence_id、relation | 回到问题句和回答句 |
| topic_aliases | normalized_alias、alias_sha256、topic_id | 保存精确别名与人工决定 |
| qa_topics | qa_unit_id、topic_id、confidence | 支持一个问答属于多个主题 |
| merge_reviews | candidate、suggested、similarity、status | 阻止静默错误合并 |

KnowledgeCompiler 还增加了 config_fingerprint。现在不仅输入原句发生变化会触发重新编译，提取器规则或输入限制等配置变化也能被识别。旧数据库在 initialize 时会安全补齐字段。

## 8. V0.3：总结框与本地界面

V0.3 的页面不是装饰，它是人工审核闭环。页面顶端展示项目、对话、Q/A、主题和待审核数量；左侧是主题目录；中间是总结框；右侧是逐句证据；底部是 Q/A 单元和消息时间线。

总结框严格分开“核心归纳”与“AI 扩展（非原始证据）”。用户点击主题后，可以看到它跨越了多少条对话和多少个证据句。右侧每条证据显示项目、对话、角色和 sentence_id。

页面使用纯 HTML、CSS 和 JavaScript，不依赖前端构建工具。这样初学者可以直接运行，也减少 V0.3 的安装复杂度。视觉上采用低干扰的纸张色和深绿色，把注意力放在知识与证据，而不是聊天气泡。

## 9. 时间线与 Context Package

时间线按发生时间展示消息和审核事件，并保留 project_id、conversation_id 与标题。当前它先回答“当时发生了什么”；后续版本再增加“观点发生了什么变化”和冲突标记。

Context Package 是跨对话与跨 AI 使用的关键产品对象。它不是偷偷赋予某个平台账号权限，而是由本地系统把用户已经授权导入的主题摘要、相关 Q/A、原句证据和 AI 扩展组装成 Markdown。用户可以检查后交给另一个 AI，形成可控、透明、可撤回的上下文传递。

Context Package 当前包含：主题标题与摘要；关联 Q/A；每个 Q/A 的来源项目与对话；逐句证据和 sentence_id；单独标记的 AI 扩展。示例文件已生成在 output/context/学习方法.md。

## 11. 实际运行方法

第一次体验可以使用项目内的合成数据，不涉及个人聊天。

```powershell
python -m ai_memory init
python -m ai_memory import examples/learning-project.json
python -m ai_memory compile
python -m ai_memory serve
```

浏览器打开 http://127.0.0.1:8765。点击“学习方法”可以看到它从“学习方法”和“学习规划”两条对话吸收 6 条证据。点击“确认可用”记录人工批准；点击“生成上下文包”显示可交给另一个 AI 的 Markdown。

单独检查底层时可使用：

```powershell
python -m ai_memory analyze
python -m ai_memory qa
python -m ai_memory merge-reviews
python -m ai_memory timeline
python -m ai_memory context 学习方法 --output output/context/学习方法.md
```

## 14. 隐私、权限与发布边界

服务默认监听 127.0.0.1，页面与 API 同源，V0.3 移除了允许任意网页跨域读取本地数据的响应头。刷新按钮只使用离线规则。系统不获取 Cookie、不保存第三方账号密码、不绕过平台权限、不自动读取用户未导出的聊天。

真实对话的正确入口仍是：用户主动导出文件；官方允许的账号或组织 API；未来明确授权的连接器。浏览器扩展只能作为较晚版本的辅助入口，而且必须限制为用户主动触发、当前页面、明确预览，不得读取登录凭据。

当前可以公开 GitHub 代码，但不应把本地数据库、真实导出、API Key 或个人截图提交。当前可以让少数可信用户在本地试用，但不能作为无鉴权公网 SaaS。

## 15. 你现在需要人工做什么

第一，运行示例并点击“学习方法”，确认总结框的结构是否符合你的学习习惯。第二，阅读 output/context/学习方法.md，判断它是否足以让另一个 AI 接着工作。第三，用 5-10 条非敏感真实对话做小范围导入，记录错误拆分、漏标签和错误归并。第四，建立 20-30 条人工期望样本，作为下一个版本的评测集。

你暂时不需要学习训练模型，也不需要先搭建 PostgreSQL。最值得先学的是 SQLite 基础查询、JSON、HTTP API、哈希与缓存、多对多关系、最小前端以及如何评价摘要是否忠实。

| Context Package | 另一个 AI 是否能继续任务 | 来源清楚，扩展与原文分开 |
| 隐私检查 | 是否含姓名、账号、密钥、私密信息 | 演示数据完成脱敏 |

建议为每个错误保存三项：原始输入、程序输出、你期望的正确结果。累积到 20-30 个样本后，它们就是第一份真正有用的评测集。以后无论更换提示词、模型还是归并算法，都必须在同一评测集上比较，避免“看起来更聪明，实际上把证据弄丢了”。

下一轮开始前，可以先回答四个产品问题：用户最常从哪个平台导入；他们更在乎“找回问过什么”还是“形成新知识”；他们愿意怎样确认标签合并；Context Package 最常被交给哪个 AI 或工作流。这四个答案会决定 V0.3.1 的导入预览和 V0.4 的评测重点。
