# ADR-0001：先做可追溯内核，再做复杂 UI

- 状态：Accepted
- 日期：2026-09-11

## 决策

采用模块化单体、PostgreSQL、对象存储和队列。原始数据、规范化数据、AI 推导数据严格分层；任何推导结果都必须带证据与 AnalysisRun。复杂 UI、独立图数据库、全自动仓库改写和大规模多租户延后。

## 原因

当前最大的不确定性是领域模型与抽取质量，而不是页面技术。先用 API 和简单视图验证问题树、时间线和证据回溯，可以最低成本发现模型错误与产品边界错误。

## 后果

前 6 周的演示可能不华丽，但数据可以重算、审计和迁移。后续替换模型或连接器不会破坏原始记录。
