# V0.4.2 · First Real Semantic Memory

状态：**Local Alpha**。这一版在现有 SQLite、Topic、Review 和本地网页上实现了首次可用的语义整理流程。它没有经过真实付费模型与真人资料的质量验收，不能称为生产就绪。

## 已实现

1. 网页支持 `.json`、`.txt`、`.md` 文件选择，以及直接粘贴文本。内容先在本地服务的临时预览区解析；确认导入前不会写入项目知识库。原始字节保存在 `source_versions`。仅在明确的 `User:` / `Assistant:` 等段落标记下拆角色，否则保存为 `unknown` 原文消息。
2. Semantic 模式使用现有 OpenAI Responses Provider 的 JSON Schema 输出。密钥仅由服务进程环境变量读取。缺少密钥时网页显示设置提示；Offline 模式仍可用。
3. 先按用户轮次做确定性预切分，再对同一对话的最多 16 个相邻轮次批量调用模型识别主题连续性；相邻同主题轮次合并为 Fragment。模型抽取带句子 ID 的主题、摘要、主张、决策、开放问题。无证据 ID 的内容不会作为证据写入。
4. 跨对话主题匹配将已有 Topic 名称、别名、摘要、关键词和本轮候选送给模型判断。决策限制为 `ATTACH_EXISTING`、`CREATE_NEW`、`ATTACH_MULTIPLE`、`REVIEW_REQUIRED`；低置信度写入待复核队列，可在左侧工作台归入已有主题、新建或忽略。小项目只发送最多 8 个候选主题，不依赖向量数据库。
5. 至少有 3 个主题时，模型可建议明确的父子关系；低于 0.85 置信度的关系不应用。页面把项目名显示为可折叠根节点。人工移动优先，后续编译不会覆盖已接受的移动。
6. 复用现有 Topic Tree、Knowledge Document、Revision 与 Review。可以重命名、移动、合并主题；新建主题、修改片段归属、报告错误。片段归属覆盖记录会在再次编译时重新应用，证据句子转到新主题。
7. 三栏网页提供主题树、AI 摘要与相关片段、可展开的原始证据。抽查入口会取最多 20 个片段，对片段边界、主题、证据、摘要支持性和重复主题逐项保存人工判断。

## 启动与首次试用

Windows 中可直接双击项目根目录的 `Open Project Memory.cmd`。或在项目根目录运行：

```powershell
python -m ai_memory launch
```

打开 `http://127.0.0.1:8765`。先用 **选择文件** 导入 `examples/v042-semantic-demo.json`，在预览后点 **确认导入**。它包含 3 段合成但贴近项目讨论的示例对话，分别使用 GPT-SaaS、Conversation Manager、Project Memory Engine 三个名称。也可以改用 **粘贴对话**，分次导入自己授权的真实对话；继续使用当前项目时，新对话会加入同一项目。

若要使用真实模型，在启动服务的同一个 PowerShell 会话中先设置：

```powershell
$env:OPENAI_API_KEY="你的密钥"
$env:AI_MEMORY_MODEL="gpt-6-sol"
python -m ai_memory launch
```

`gpt-6-sol` 是目前官方文档列出的支持 Responses API 与结构化输出的模型；能否调用取决于你的 API 项目权限与计费状态。模型及价格以 [OpenAI 官方模型文档](https://developers.openai.com/api/docs/models/gpt-6-sol) 为准。密钥可从 [官方 API 入门页](https://developers.openai.com/api/docs/quickstart) 指向的控制台创建。以上 PowerShell 变量只对当前窗口有效，关闭窗口后不会保留密钥。

在网页选择 **Semantic**，点击 **编译主题树**。完成后，依次打开项目主题、相关片段与右侧证据。点击右侧的证据句子，可以看到它所在的完整原始对话；误归类可以通过“修改归属”保存。选择 **抽查片段** 对最多 20 个片段做人工评价。没有密钥时选 Offline，仍能验证导入、证据和人工纠错链路。

## 数据与缓存

数据库 schema 为 V6，新增 `semantic_segment_cache`、`semantic_match_cache`、`semantic_hierarchy_cache`、`semantic_review_queue`、`topic_keywords`、`fragment_topic_overrides`、`issue_reports`、`fragment_evaluations`。仍使用原有 `fragments`、`topics`、`topic_evidence`、`topic_tree_nodes`、`knowledge_documents`。缓存键包含原文指纹、模型或候选主题状态。未变化的项目编译直接跳过；`force=True` 时片段提取与语义分段仍可命中缓存。已确认的主题同义名会保存为别名，避免再次请求模型。

## 已知边界

- 语义片段边界落在用户轮次之间；单条极长消息内部的多个议题当前由抽取器分配多个主题，尚不会拆成多个独立 Fragment。
- 匹配是小规模候选筛选加模型判断。待复核队列目前只提供归入、新建或忽略；复杂多主题归属仍需使用片段修改功能。
- 真实 API 调用取决于用户本机的密钥、模型权限、网络和费用。本仓库没有保存密钥，也没有在自动测试里请求付费服务。演示数据是合成的，语义正确性必须由用户用真实对话人工抽查。
- 文本粘贴仅可靠识别显式角色前缀。其他格式完整保存为原文，不猜测角色。
- 本地服务只绑定回环地址；预览内容保存在当前服务进程的临时内存，重启后需要重新预览。

## 验证

```powershell
python -m unittest -q
```

自动测试覆盖原有能力和粘贴、文件预览、语义分段缓存、跨对话归并、证据追溯、人工归属与评价、无密钥提示。它们验证流程正确性，不能代替真人语义质量评价。
