# V0.4 Alpha：项目主题树编译

V0.4 在 V0.3 的 SQLite、Q/A、Topic、Evidence、Knowledge File、Revision 和 Review 之上增量实现。默认仍是本地离线 Alpha，不提供公网鉴权或云服务。

## 本版流程

`源文件/文件夹 → 预览 → 确认导入 → 用户轮次片段 → 逐片段主题提取 → 保守主题匹配 → 项目主题树 → 摘要、Q/A、原句`。

```powershell
python -m ai_memory preview examples/learning-project.json
python -m ai_memory import examples/learning-project.json
python -m ai_memory projects
python -m ai_memory compile-project <上一步返回的project_id>
python -m ai_memory tree <project_id>
python -m ai_memory serve
```

打开 `http://127.0.0.1:8765`，也可以在页面输入本机 JSON 文件或文件夹路径，先扫描预览，再确认导入。选择项目后点击“编译项目”。页面显示片段分析进度、可展开主题树、主题相关片段与 Q/A、逐句证据和原始消息链接。Rename、Move、Merge 先生成提案，再由用户确认应用。

默认 `heuristic` 是离线规则基线，适合验证流水线；非学习领域的主题质量需要人工核对。显式选择 OpenAI 时，需要设置 `OPENAI_API_KEY` 并提供模型 ID：

```powershell
$env:OPENAI_API_KEY="..."
python -m ai_memory compile-project <project_id> --extractor openai --model <model-id>
```

按片段缓存提取结果，同一内容和配置不会重复请求模型。OpenAI 提取器用结构化 JSON，验证所有返回的证据 ID；主张、决策和待解决问题没有证据时会被拒绝。摘要仍需要人工判断是否忠实，不能仅凭 ID 存在就视为事实正确。

## 来源生命周期

预览会报告 `NEW`、`UNCHANGED`、`CHANGED`、`REMOVED` 或 `FAILED`。同一路径文件变化后，原始文件字节保存在 `source_versions`，旧对话和消息保留为 inactive，新版本进入同一项目；受影响文档标记 dirty/stale。对文件夹再次预览时，原先导入但已不在文件夹里的 JSON 会显示 `REMOVED`，确认导入后将其停用。单个文件可用 `python -m ai_memory remove-source <path>` 停用。原始消息可继续按 ID 查询，常规搜索与编译只读取活跃版本。每个文件的导入在 SQLite 事务内完成；文件夹中有解析错误时不会开始批量导入。

## 数据迁移

数据库 schema 从 4 升到 5。`initialize()` 在原库上添加 `conversations.source_id/source_sha256/active`、`messages.active`、`knowledge_documents.dirty`，并创建 source_files、source_versions、fragments、fragment_evidence、fragment_analysis、fragment_topics、topic_tree_nodes、tree_change_proposals、topic_insights 等表。首次对旧来源执行相同文件导入时会补登记来源。正式数据升级前建议备份 SQLite 文件。

## 人工评测

```powershell
python -m ai_memory eval-export <project_id> --output docs/evals/goldens/my-review.csv
# 在 CSV 中填写 expected、verdict（pass/fail）和 notes
python -m ai_memory eval-report docs/evals/goldens/my-review.csv
```

导出行覆盖片段边界、主题归属、错误/遗漏合并、摘要和结构化洞察的证据，以及原句定位。`unsupported_knowledge_rate` 只根据已人工审阅的摘要、主张、决策和待解决问题行计算；未审阅不会被计作通过。仓库内只有合成 fixture，真实或脱敏项目样本需要用户自行提供并审核。

## 已知限制

- 初始树以项目为根、主题为子节点；更深层结构由 Move 提案调整。自动层级建议与 Split 尚未实现。
- 片段边界按用户轮次确定；特别长的单次输入暂不再语义切分。
- 相似名称只提示人工判断，不能保证消除所有重复主题；未加入向量检索。
- 当前知识文件摘要仍沿用 V0.3 编译逻辑。结构化洞察绑定证据，但不代表程序能判断语义真伪。
- 文件夹批量导入是逐文件事务；若中途出现磁盘/数据库故障，已完成的前序文件不会自动回滚。
- 无鉴权的本地 HTTP 服务不能暴露到公网。未提供 Claude/Gemini/Qwen 等未经验证的真实导入器。
