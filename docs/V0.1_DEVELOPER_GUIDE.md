# V0.1 开发与使用指南

## 本版本解决什么

V0.1 建立供应商无关的数据底座。它不依赖 OpenAI、Claude 或 Gemini SDK，也不会自动抓取任何账户。用户把有权使用的导出 JSON 交给程序，程序保存项目、对话、消息、逐句来源、问题与直接回答关系，并允许跨项目搜索。

## 为什么使用 SQLite

SQLite 随 Python 提供，不需要安装数据库服务器，适合学习和验证领域模型。当前所有 ID 都是确定性的 UUID5；同一文件再次导入会由 SHA-256 阻止重复。未来迁移 PostgreSQL 时，表的职责仍可保留。

## 快速开始

```powershell
python -m ai_memory init
python -m ai_memory import examples/learning-project.json
python -m ai_memory projects
python -m ai_memory questions
python -m ai_memory search 复习
python -m ai_memory serve
```

API 默认地址为 `http://127.0.0.1:8765`：

- `GET /health`
- `GET /v0/projects`
- `GET /v0/questions`
- `GET /v0/projects/{project_id}/conversations`
- `GET /v0/projects/{project_id}/questions`
- `GET /v0/search?q=复习`
- `GET /v0/messages/{message_id}`

## 通用导入格式

根对象包含 `provider`、`project_id`、`project_title` 与 `conversations`。每个 conversation 包含 messages；消息包含 `id`、`role`、`text`、可选的 `created_at` 与 `parent_id`。

ChatGPT `conversations.json` 也可以直接导入。因为账户级导出通常不能可靠表达你在界面中定义的项目归属，V0.1 要求你准备只包含目标会话的 JSON，或通过 `--project-title 学习` 指定逻辑项目名称。

## 追溯方式

消息保存原始外部 ID、父消息 ID、原始 JSON 和确定性内部 ID。句子表保存：message_id、段落序号、字符起止位置、文本与 SHA-256。搜索结果直接返回这些定位字段，所以任何命中都能回到原始消息。

## V0.1 的明确限制

- 目前只接受 JSON；附件和 PDF 后续加入。
- 问题识别采用“每个用户轮次都是一次请求”的确定性规则。
- 只把父节点为用户消息的助手消息标记为直接回答。
- 搜索使用 SQLite 子串匹配，适合原型，不等于语义搜索。
- 没有调用外部 LLM，也没有生成知识文件树。
- API 为本地只读开发接口，尚无鉴权，不能直接暴露到公网。

## 你可以从本版本学习什么

1. JSON、对象、数组与序列化。
2. SQLite 表、主键、外键、唯一约束和索引。
3. 数据库事务为何能避免“导入一半”。
4. SHA-256 与幂等导入。
5. Connector/Adapter 如何隔离不同 AI 导出格式。
6. HTTP GET、查询参数和 JSON 响应。
7. 单元测试、临时数据库和回归 fixture。
