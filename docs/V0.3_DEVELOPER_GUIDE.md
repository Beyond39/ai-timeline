# AI Project Memory V0.3 开发与体验指南

版本：0.3.0（本地产品 Alpha）  
实现日期：2026-09-13

## V0.3 的版本边界

V0.2.1 解决“知识怎样可靠产生”；V0.3 解决“普通用户怎样看见、核对并带走这些知识”。因此 V0.3 新增本地三栏总结界面、Q/A 列表、时间线、审核按钮和 Context Package。它仍不是公网 SaaS，也没有自动读取任何 AI 账号。

## 总结框

浏览器打开 `http://127.0.0.1:8765` 后，左侧展示跨对话主题，中间展示核心归纳与明确标记的 AI 扩展，右侧展示每条证据的项目、对话、角色和句子 ID。页面下方展示 Q/A 单元与原始消息时间线。

用户可以把知识标记为“确认可用”或“退回复核”。每次操作都会更新知识文档状态并写入审核事件。点击“生成上下文包”，会把主题摘要、关联 Q/A、原句证据及非原文扩展组织成 Markdown；这份内容可以复制给另一个 AI，从而实现可控的跨对话、跨项目上下文传递。

## 使用方法

```powershell
python -m ai_memory init
python -m ai_memory import examples/learning-project.json
python -m ai_memory compile
python -m ai_memory serve
```

然后只在本机浏览器打开 `http://127.0.0.1:8765`。如果默认端口被占用，可以执行 `python -m ai_memory serve --port 8877`。

补充命令：

```powershell
python -m ai_memory analyze
python -m ai_memory qa
python -m ai_memory merge-reviews
python -m ai_memory context 学习方法 --output output/context/学习方法.md
python -m ai_memory timeline
```

## 新接口

| 接口 | 作用 |
|---|---|
| GET /v0/dashboard | 返回项目、Q/A、主题、文档和待审核数量 |
| GET /v0/qa-units | 返回派生 Q/A 单元与主题 |
| GET /v0/merge-reviews | 返回待人工判断的相似标签 |
| POST /v0/merge-reviews/{id} | 合并或保留两个主题 |
| GET /v0/timeline | 返回带项目与对话坐标的时间线 |
| GET /v0/context/{topic} | 生成主题上下文包 |
| POST /v0/refresh | 本地执行 Q/A 分析和离线知识编译 |
| POST /v0/review | 批准、退回或重置总结 |

完整草案位于 `contracts/openapi-v0.3.yaml`。

## 隐私与权限

页面和接口默认只监听 127.0.0.1，并移除了允许任意网页跨域访问的响应头。刷新按钮调用默认离线规则，不会自动向外部模型发送内容。OpenAI 提取仍只有在命令行显式选择、提供模型和 API Key 时才启用。

本版不保存 ChatGPT、Claude 或 Gemini 的登录凭据，不抓取 Cookie，不绕过平台权限，也不宣称能直接读取用户账号。真实对话仍应通过用户主动导出或未来经过平台授权的连接器导入。

## V0.3 验收结果

自动测试共 15 项，全部通过。新增测试覆盖 Q/A 缓存、证据关系、标签哈希边界、近似标签复核、上下文包、时间线坐标、本地 HTML 页面、Dashboard API 和网页审核写入。示例联调得到 2 个 Q/A 单元、5 个知识主题、5 份知识文件和“学习方法”主题的 6 条原句证据。

## 尚未完成

V0.3 仍缺少真实 Claude/Gemini 导入适配、删除同步、冲突检测、全文向量检索、登录与多用户隔离、安装器、云部署和大规模评测。当前界面适合个人本地试用和开源演示，不适合暴露到公网或处理未经清理的高度敏感资料。

## 下一版本最重要的三件事

1. 导入预览与删除同步：用户先看将导入什么，也能让来源删除传播到派生知识。
2. 可信评测：建立人工标注样本，量化问题拆分、标签、证据召回、错误合并和摘要忠实度。
3. 真实连接器：在平台允许的导出/API边界内逐个支持，而不是依赖脆弱的网页抓取。
