# AI Project Memory V0.2.1 变更与学习指南

版本：0.2.1（底层能力阶段）  
实现日期：2026-09-13

## 结论

V0.2.1 把“一个对话里可能混着多个问题”变成了真实的数据结构。系统逐条读取对话中的用户问题与直接回答，形成独立 Q/A 单元；每个单元仍绑定问题句、回答句、项目和原始对话位置。它不训练新模型，也不覆盖原文。

核心流程是：原始对话 -> 按对话 Map -> Q/A 单元 -> 候选标签 -> 精确标签解析 -> 主题关联 -> 跨对话知识编译。后续可以把离线规则替换成用户授权的 LLM 结构化输出，但数据库结构保持不变。

## 哈希与相似度的正确分工

哈希只处理“是否完全相同”：标签规范化后计算 SHA-256；问题与回答合并后计算内容哈希；对话内容、提取器版本和提示词版本共同形成缓存键。只要输入和处理配置没变，就能复用结果。

哈希不能判断“学习方法”和“学习技巧”是否同义。V0.2.1 因此把精确匹配与近似判断分开：精确别名直接归入已有主题；文字相似只生成 merge review；最终由人选择 merge 或 keep_separate。程序不会静默合并可能不同的知识。

## 新增数据表

| 表 | 用途 |
|---|---|
| analysis_cache | 按对话保存可复用分析结果与处理配置 |
| qa_units | 保存问题、回答、摘要、内容哈希和状态 |
| qa_evidence | 绑定 Q/A 与问题句、回答句 |
| topic_aliases | 保存标签规范化结果、哈希和人工别名 |
| qa_topics | 建立 Q/A 与主题的多对多关系 |
| merge_reviews | 保存相似标签的待人工判断任务 |

数据库会从旧版本自动补充新表和编译配置指纹字段；原来的项目、对话、消息、句子、主题和修订数据不需要重建。

## 实际验证

“学习”示例包含 2 条对话、2 个问题和 2 个直接回答。V0.2.1 生成 2 个 Q/A 单元、8 条 Q/A-句子证据关系和 6 条 Q/A-主题关系。第二次分析命中 2 条对话缓存。测试同时证明：格式不同但含义相同的精确标签可以得到相同哈希；语义可能相似但文本不同的标签不会得到相同哈希；相似标签只进入人工复核。

## 你需要学习的内容

1. 一对多与多对多关系：一个 Q/A 可以对应多个主题，一个主题也可以吸收多条对话里的 Q/A。
2. 内容寻址：理解为什么内容哈希适合去重，却不适合理解语义。
3. 幂等与缓存：同一对话、同一提取器版本、同一提示词版本不重复付费处理。
4. 人在回路：模型适合提出候选，人负责高风险合并和最终批准。
5. Map-Reduce：先逐对话分析降低输入规模，再跨对话汇总主题。

## 当前限制

本版 Q/A 摘要和标签默认由离线结构规则产生，目的是验证数据流、缓存和证据关系。它不等同于成熟的语义理解。真实数据测试时，应先使用少量非敏感导出，人工标注 20-30 条期望结果，再决定 LLM 提示词、嵌入模型和归并阈值。
